# The color tool

What this page covers: the Colors button that tries a whole dark color combination, and the saved color combinations. Back to the [README](../README.md).

- **The saved color combinations of the color tool** (`stackshot/web/colorcombos.py`, the routes block in `stackshot/web/server.py`, `tests/color_combos_scenario.py`). One list for the whole instance, oldest first, kept in `<state>/color-combos.json` (`{"combos": [{"id": "<8 hex>", "name", "values", "saved": <epoch>, "via": "board" | "sala-web"}]}`; written whole to a temporary file, fsynced and swapped in with `os.replace`, under a lock; a file that does not parse is moved aside to `color-combos.json.bad-<epoch>` and the list starts empty; a file that cannot be read, or that does not parse and cannot be moved aside, is a 503 and is left as it is). A combination carries all 14 keys, each `#rrggbb` in lowercase hex: `bg` page background, `card` cards, `fg` body text, `mut` muted text, `line` lines, `ibd` button outlines, `link` text and links, `solid` solid fills, `onsolid` text on solid fills, `labbg` small label fill, `labfg` small label text, `labbd` small label outline, `disbg` disabled fill, `disfg` disabled text; the server runs no contrast check (the app that applies a combination does). A name is NFC, stripped, 1 to 40 characters with no control, format or line-separator character (Unicode categories Cc, Cf, Zl, Zp: a tab, a line break, a zero-width space, a bidi override), and unique when case is ignored: a save under a name the list has replaces that combination and keeps its id. At most 50 combinations (a new name past that is 409 "the list is full, delete one"); a request body is at most 4 KB. Routes for the board's own page, signed in and from the board's origin like `/prefs/panel-order` (403 otherwise, a read too), JSON only (415), size (413): `GET /colors/combos`, `POST /colors/combos` (`{"name", "values"}`) and `POST /colors/combos/delete` (`{"id"}`; an id the list does not have is no error). Routes for the fleet tool's web server, by the machine token as the other `/client` routes (401 without a valid one; 403 unless its machine is in `[project_agent] form_machines`): `GET /client/colors/combos`, `POST /client/colors/combos` and `POST /client/colors/combos/delete`, whose body adds `"sender": "sala-web"`, a label that must also be in `form_senders` (the same gate as the For you writes; 403 otherwise). Every answer is `{"combos": [...], "max": 50}` with `Cache-Control: no-store`; an error is `{"error": "<a plain sentence>", "field": "<the failing key, name, values, id or sender, else null>"}` with status 400 (bad name or values), 403, 409, 413, 415 or 503, except the machine routes' 401, which is the plain text of every `/client` route. On a read-only standby copy a post is the usual 503. The paths are not under `/prefs/` (a post there drops the kept home page) and the two-segment `/client/colors/combos` paths do not meet the single-segment `/client/{what}` routes.

- **The color tool: a Colors button to try a whole dark color combination** (`shared/colortool.js` is the tool, one shared source; `stackshot/web/ui/colortool.py` is stackshot's side: its settings and the two script blocks the pages carry, hooked into `_APP_HEAD` and `_FAB_PAIR` in `stackshot/web/ui/render.py`, with the mount `#panel-colors` that `_panel_frame` draws; `tests/color_trial_scenario.py` and the Colors block of `tests/phone_width_check.py`). On the dark theme a button, a bare two-color circle (no text and no frame: the live page color on its upper left half, the live solid fill on its lower right, split by a diagonal line; the button is named Colors by its `aria-label`), sits at the very bottom of the side panel, outside the sections that move and clear of the reload and Back to top buttons. It opens a panel upward from itself: `position: fixed` in the page body, above the reload and Back to top buttons, with its own scroll when it is taller than the screen (it fits a 360 px phone). The panel hangs from the button. At its bottom, beside the button, one box holds Presets (Original orange theme, Sky, Mint, Violet, Rose: the Original orange theme is the dark look the board ships, an empty map that sets nothing and so is what Reset returns to; a click on Sky, Mint, Violet or Rose sets that scheme's text color, solid fill, white label on it and small labels, and keeps the shipped neutrals; a look stored or saved earlier from a preset that has since been removed is a map of fields and applies as it did) and Saved combinations together; above it a Fields button folds the 14 fields away, and opening it grows the panel upward, away from the button (the panel is then scrolled to its end, so the Fields button, the presets and the saved list stay in view). The folded part is a stack of boxes: Surfaces (page background, cards, lines), Text (body text, muted text, text and links), Buttons (button outlines, solid fills, text on solid fills, disabled fill, disabled text), Small labels (fill, text, outline). The Preview box (a Send, a disabled Send, a button, a disabled button, a "Your move" tag, a recommended badge, a link) is outside the fold, under the Fields button, so it stays in view. The fields start folded and the choice is kept in this browser. Each box heading keeps the side panel's section style (small uppercase) but is in the link color, the live text and links field, and the fields under it are indented, so a heading is not mistaken for a field. Reset returns to what is shipped: the dark default of every page (one orange `#f0a06a` for links and fills, the near-black `#1f1f21` on the fills, the small labels orange text `#f0a06a` on a dark brown fill `#3a2619`, and the disabled buttons a flat grey fill with grey text). The 14 fields are each a native color input and a hex box that apply at once. Status colors are not in it. A field left alone is the shipped value or follows the others: cards and lines follow a set background, the label on a solid fill is chosen for reading (dark or white), the small label follows the text orange, the disabled pair follows the Send faded to half. While nothing they follow is set, those five are the shipped values; once the text orange, the page or cards is set the small label is worked out from it, and once the solid fill, its label or the page is set the disabled pair is the Send faded to half. **The look you apply is kept in this browser only** (the `localStorage` key `stackshot-color-trial`, a map of the fields that are set, `#rrggbb` in lowercase; an older `{text}` is read as the text and links field; whether the Fields fold is open is kept beside it under `stackshot-color-trial:fields`, `1` when open and absent when folded, the default). It sets custom properties inline on `<html>` and two classes (`ct-on` solid fills, `ct-wl` a lighter label hovers toward black) and leaves the shipped stylesheet and its tokens as they are (`--orange` keeps its value; the text orange is read through `--orange-text`, the solid through `--orange-solid`, the label on it through `--on-solid`). The shipped dark look is the stylesheet's own: `--orange` `#f0a06a`, `--on-acc` `#1f1f21`, `--ibd` `#929190`, and five dark tokens (`--lab-bg`, `--lab-fg`, `--lab-bd`, `--dis-bg`, `--dis-fg`) with the dark rules in `stackshot/web/ui/render.py` that draw the orange small labels and the disabled buttons from them; the tool sets those five inline once a look touches them (a small-label field or one it follows, a disabled field or one it follows). `tests/dark_default_scenario.py` pins the dark default against its own 14 fields (the neutrals that `shared/colortool.js` gives every preset, and the three small-label fields: orange text `#f0a06a` on `#3a2619`, outline `#3a2619`) and that the light theme's token block (page, text, lines, cards, the orange and the label on it, the input tokens) keeps its values, and `tests/dark_default_check.py` is the same proof in a browser, by hand. The light theme is untouched: nothing is drawn or applied there. `tests/orange_scenario.py` reads the pages without the tool's script blocks and skips `shared/colortool.js`, which carry the presets, and only those. **The gate** runs in the page on the combination as it resolves (a preset, a saved one and a stored one included; the server runs none). A change that breaks one of these pairs is not applied, and the panel says "Not applied" with the pair and its ratio: body text on the page 11:1 (the background gate: a page lighter than about `#303030` is refused) and on cards 7:1, muted text on the page and cards 4.5:1, button outlines on the page and cards 3:1; a stored look that fails them is cleared at load, its surface and text fields. These pairs are applied with a note and the ratio instead ("Below its limit"), and a preset that has one is marked: text and links on the page and cards 4.5:1, solid fills against the page and cards 3:1, text on a solid fill 4.5:1 at rest, hovered and pressed, a small label's text on its fill 4.5:1 and its outline against cards 3:1, the disabled text on its fill 3:1, lines against cards 1.15:1. Every preset reads clean on all of these pairs (the white label of Sky, Mint, Violet and Rose reads above 4.5:1 at rest, hovered and pressed), and a test pins that. With `gate: "warn"` (an app's choice, not stackshot's) the first six pairs are only notes with their ratio too, a saved, stored or typed combination always applies and a stored look is never cleared. The dark disabled rule of the stylesheet gives every disabled button on the page, the panel's own two disabled preview buttons included, the flat fill and text of the two disabled fields at full opacity, the idle Send included; the light theme keeps its faded disabled buttons. **Saved combinations** are kept on the server, one list for the instance and shared with the fleet tool's web page, through `GET /colors/combos`, `POST /colors/combos` and `POST /colors/combos/delete` (see the paragraph above): the panel reads the list when it opens, Save stores the 14 resolved values under a name (the same name, case ignored, replaces it in place), a saved name applies in one tap (through the gate) and Delete asks once more. The page's only requests are those three, from the board's own address; a refusal (not signed in, the list full, a bad name, the file unreadable, offline) shows the route's message in the panel and never changes the look that is applied. **The shared-source contract.** `shared/colortool.js` is one file that more than one app draws: its first line is `/* colortool v3 */`, it carries no placeholder and no name of an app, and another app pins a verbatim copy of it (not an edited one) and passes its own settings in a `cfg` object. The file changes only with a version bump (its first line and `ColorTool.version`), and the apps that pin a copy are told, so each takes the new version on purpose. It defines `window.ColorTool` with `version`, `applyStored(cfg)` (in the head: injects `cfg.css` once and applies the stored look before the first paint; draws nothing), `init(cfg)` (at the end of the body: draws the button in `cfg.mount` and the panel in the body), `remount(mount)` (moves the button into a new mount element after the app re-rendered its own; the panel and its state stay) and `engine(cfg)` (the pure functions and constants, for tests). The `cfg` fields are `storageKey` (the `localStorage` key; the Fields fold is kept under that key plus `:fields`), `shipped` (the 14 values in use with nothing set, an object or a function called on every apply and never cached; the five that follow others, the three small labels and the disabled pair, are the app's own values while nothing they follow is set and are worked out from the live fields once one is, so an app whose shipped label or disabled look is not what that rule gives still sees its own in the panel; a key left out or not `#rrggbb` is always worked out), `vars` (`{field: [custom properties]}` set inline when the field is set; cards and lines also with a set background), `onApply(resolved, stored, set, addClass, engine)` (runs on every apply while dark, Reset and the Original orange theme included, after the tracked properties and classes were removed; `set` and `addClass` are tracked, so Reset removes what they set), `isDark()` (default: `data-theme`, else the system scheme), `gate` (`"refuse"`, the default, or `"warn"`), `css` (an extra stylesheet, injected once), `mount` (a selector or an element), `preview` (trusted HTML of the preview strip; without it that box is left out) and `api` (the saved list's base URL; without it that box is left out). Stackshot's settings are in `stackshot/web/ui/colortool.py`; `deploy.sh` restarts the server for a change under `shared/`.
