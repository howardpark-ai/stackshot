# The For you list and the Closed page

What this page covers: the list of notices for the owner, Watch and Mute, the Slack post for an urgent row, the machine-token routes of the web form, and the Landed list that is now the Closed page. Back to the [README](../README.md).

**The For you list** (`stackshot/web/foryou.py`). A notice that is for the owner himself is a row in a list, never a turn
of a front agent. Rows live in `<state>/for-you.json` (a small JSON file, written whole and swapped in with `os.replace`), newest first, at most 200;
a row marked seen leaves, and its key is remembered for 30 days so the same event does not come back. What makes a row: a watched item's close, reopen,
move to `needs: decision`, failed check (`wait_failed`) or a due date within 24 h (an urgent row). A failed release makes no row: the message `release.sh`
sends to `[release] report_to` (default `projects/example`) goes to the builder only, and the owner hears of it through the item the release serves. A row of a kind that is no longer listed (the old `release_failed`) is dropped when the file is read. A row is made when the state change is saved (`server._save` → `_foryou_on_save`, in `stackshot/web/foryou_events.py`), so a session's
write, the server's own pass and the done check all count; his own answer on the board makes no row, and takes the item's decision row off the list.
**Watched by default:** an item with a `said` entry, a quoted attribution or a board answer of his on it, and an item that waits on his decision.
**Watch / Mute** is per item, set on the item's page (a button each, behind the board's sign-in, the page's token and the board's own origin) and stored
in the same file; Mute stops rows for that item, Watch adds an unwatched one, Default removes the flag. The router's automatic `[for <owner>]` passes of
a close are gone with this (the `close-words` rule now only rules an old notice merged); a message a session sends on purpose with `[for <owner>]` is
not touched. **Slack:** stackshot has no Slack posting path of its own (anchor-hub only receives Slack), so an urgent row calls
`_for_you_slack_post` (stackshot/web/foryou_slack.py), which runs `[for_you] slack_command` (an argv, the row's text on its standard input; empty = no Slack, the row only);
a row is posted once (`slacked`). The post runs on a worker thread of its own, in a session of its own, and a command that outlives `_FORYOU_SLACK_TIMEOUT` (30 s, in stackshot/web/foryou_slack.py) is killed with its whole process group. A failed post is logged and tried again by the due-date pass, at most 3 tries in all (`slack_tries` on the row) and only while the row is under 24 h old. A `for-you.json` that does not parse is moved aside to `for-you.json.bad-<epoch>` and the list starts empty (ids go on from the highest one still readable, else from the clock). If a close with his words cannot be written as a row, the old `[for <owner>]` notice goes to the front owner and the writer's reply says so. The board page carries a "For you" section (item link, what happened, when in the instance timezone, a "seen" button, "mark all seen");
`stackshot/fleet/client.py get for-you` prints `{"generated", "rows": [{id, kind, item, project, what, url, urgent, ts, when, slacked}], "flags": {item: "watch" | "mute"}}` as JSON.

**For the fleet tool's web server**, which holds the machine token and has no board cookie or page token, the same two writes are machine-token routes:
`POST /client/for-you/seen` (mark a row, or all, seen) and `POST /client/items/{key}/watch` (Watch / Mute / Default; `stackshot/fleet/client.py post for-you-seen`
and `stackshot/fleet/client.py post watch`). They are the New session form's caller only (`_form_call` in `stackshot/web/project_form.py`: `sender` is a label in `[project_agent] form_senders` and
the token's machine is in `form_machines`; defaults: no sender label, so the form is off until `form_senders` names one, and no machine, `form_machines` = `[]`). Any other caller gets 403 with the reason: a session
that holds the machine token must not be able to mute his items or clear his list. Each change is logged to stderr with the sender and publishes the board.
(The label is the caller's own word, as for the form's other calls: the machine check is what the token proves.)

**The Landed list** (`stackshot/web/landed.py`; kept until he clears it). An item an agent finishes and closes reached him only when his words
were on it (the For you list, hidden). Every close that he did not make himself, to the outcome done or dropped, is now one record in `<state>/landed.json` (a small JSON file written
whole, one record per item: its latest close, with the close's clock, the outcome, who closed it as the writer was stored, the project and when he cleared it, 0 = not). The record is made where a
write is saved (`_landed_on_save` in `stackshot/web/foryou_events.py`, beside `_foryou_on_save`): a session's close, and the server's own close on a done check (no closer, shown as "stackshot"). **His own close makes none**:
his answer on the board (`author` is he, e.g. "drop it" on a watcher's ask), or a write whose sender is he. A close to any other outcome (superseded, unrecorded) lands nothing. A reopen takes
the item's record off; its next close is a new record, uncleared, whatever the first one's state. A record is kept 60 days (a file that cannot be read is never written over: the writers raise and leave it, the board reads an empty list; a bad hand-edited record is skipped). It is a store of its own because a For you row exists only for
a watched item, carries neither outcome nor closer as fields, and leaves the list when seen. **Like a phone's notifications, an entry stays until he clears it**: there is no seen state, and opening the page clears nothing. **The board's header** carries `Landed N` as the fourth of its five count cards (Your move, Agents at work, Waiting, Landed, Completed; `Board.home_counts`), a link to
`/landed`; and at 0 the card is still drawn, its number muted. **The count and the page read one function**, `Board.landed_rows` (every uncleared close of the 60 days whose item is still closed with an outcome that lands); the count is its length and the page lists its rows, so the two cannot differ. **The page** (`GET /landed`, `Board.landed_html`, behind the board's sign-in, rendered on
request) lists them grouped by scope (for example team, personal and infra, as sala's sidebar groups them: the project's scope from `stackshot/projects/projects.py`, set on purpose or derived from its page and its agents' names, in `[project_scopes]` order) in one foldable subsection per scope, the same markup and the same code as home's lists (`Board.scope_sections`, `stackshot/web/ui/groups.py`): the scope's name and its entry count in the summary, open by default, the entries of a scope newest first, no row naming its project (home's rows do not; opening the item shows it; clearing a line never moves a subsection); the Last 14 days section below draws its rows the same way (the rows of the page shown); each entry reads as a notification: a Clear button first, then the subject as the headline with the close's age beside it ("12 min ago", "3 h ago", "yesterday"; the exact time in the board's zone on hover; the page script redraws it every 30 s), the close reason under it (as large and dark as the subject, wrapped, never cut) and a quiet line with the item id (a link) and done or dropped; who closed it is on the item's page, not here. **Clear all** sits at the top, above the list. **Clearing** is per close
(`landed.key`: item and close clock): a line's Clear and Clear all post the keys they carry to `POST /landed/clear` (the For you seen route's gates: signed in, from the board's
own origin), which republishes the board so the header count drops; a close that lands after the page was drawn is not cleared by it. **Undo**: the page's script sends Clear, Clear all and Undo with `fetch` (`Accept: application/json`, answered `{"ok": true, "changed": n}`; the form post, 303 back to the page, is the fallback without JavaScript) and leaves a cleared line where it is, dimmed, its Clear replaced by an Undo that stays until the page is reloaded (Clear all leaves a per-line Undo on each line it cleared); an Undo posts to `POST /landed/unclear` (same gates, same 64 KB cap), which restores only a record that is cleared, still the close the key names and inside the 60 days (`landed.unclear`); an unknown, uncleared or old key does nothing. The home Landed count is the server's: each change republishes the board, so the header follows (an open home page picks it up with its in-place update). The old `POST /landed/seen` is kept as the same route for a page still open. A cleared record stays in the file until it is 60 days old, so the same close cannot come back. A record the first release marked `seen` (opening the page did that) is uncleared: he never cleared it. Nothing from before the release is
back-filled. No tool changes: a session does not read this list.

- **On the board at the root the Landed page is the Closed page** (`Board.landed_html`, `Board.home_counts` in `stackshot/web/ui/render.py`, `GET /closed` in `stackshot/web/server.py`). The fifth home card says "Closed": its number is the items closed in the last 14 days (done, dropped and superseded alike, `len(Board.done)`), and on the card's label line, right after the word "Closed", the count "N new" as green text (no pill: the number above it stands alone), N the closes of agents that the owner has not cleared yet (`Board.landed_count`, what the Landed card used to count): all of the 60 days `stackshot/web/landed.py` keeps an uncleared close, not only the last 14, so the count can be larger than the number, as the Landed card's count was (the item is read from all the board's rows, so a close older than 14 days shows its own title, outcome and reason, and leaves the New section only when cleared or past the 60 days); no count at 0. The count keeps the card at 60 px and never clips, and the word "new" is never dropped: where the label line is too narrow for "N new", it moves up to the number line, beside the number (positioned against the number, in the card's padding room, never clipped), chosen by the card's own width with a container query, one width for each length of N (the count's class says it: `w2`, `w3`, `w4` for two, three, four digits or more, none for one digit), so a card of 120 px shows "N new" on the label line in full for up to three digits. The word is the string catalog's `home.new_word` (`stackshot/web/i18n_catalog.py`; the file of another language may give a longer one, and the page reads it in the request's language): a longer word raises the widths in proportion to its estimated width, so it moves up sooner and still fits; where the number, the count and the word are wider than the card's content, the card's `--need` (their width in px, estimated) shrinks the number and the badge in proportion, but the badge never goes under 9 px (a count of many digits in a narrow card stays readable; only a word so long that the number would fall under its own 6 px floor lets the badge go lower): the number takes what the badge at its own size leaves (the card's `--nk` and `--bk`, the number's width at 22 px and the badge's width per px of font), so the pair still stays inside the card. A card still measures its own width for these rules, so the five cards stay one size. The page it links to is titled Closed and has two sections: **New** (the uncleared closes of the last 60 days, grouped by scope and project, with Clear and Clear all, as the Landed list was) and **Last 14 days** (the paged list that was the Completed section; `#completed` is still its anchor). The old address `/landed` (any `?page=N` kept) answers a 301 to `/closed`, never cached; the Clear, Clear all and Undo posts keep their `/landed/clear` and `/landed/unclear` addresses (they are not pages), and a form post without scripts returns to `/closed`. `tests/ui_kit_scenario.py` checks the card's markup and CSS with the count shown and hidden, `tests/board_pages_scenario.py` the route and the redirect, `tests/hcard_height_check.py` the card heights and the count's place (and, at eight window widths in three zooms with the panel open and closed, for counts of one to four digits and for a longer stand-in word, that the word shows whole inside the card), and `tests/phone_width_check.py` the count at phone widths and in a 120 px card.
