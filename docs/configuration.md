# Configuration

What this page covers: the config file, where it is read from, and the keys for the instance, paths, pages, subjects, descriptions, the page rule, the audit, asks, publishing, the GitHub mirror and the scopes. Back to the [README](../README.md).

An instance is one TOML file outside this repository: `$STACKSHOT_CONFIG`, else `~/.config/stackshot/stackshot.toml`,
else a `stackshot.toml` next to the code, else the shipped `stackshot.example.toml` (see `stackshot/core/config.py`). Only one file is
read; nothing is merged. The table lists every key of `stackshot.example.toml` with its example value. "Yes" in the last
column marks what a second person must set; "if used" marks what matters only with that optional piece.

| `paths.state` | `"~/.local/state/stackshot"` | Everything the instance writes for itself: site, ledger, messages, inbox, clients, anchor-hub state. | |

| `pages.flavor` | `"plain"` | How a session is told to update its page: plain (edit `<paths.brain>/<key>.md`, commit and push) or gbrain (through gbrain's tools). With plain, the server itself writes pages as markdown files in `paths.brain` (a new project's page, the router's timeline notes, the page-debt pass) and runs no git: committing that checkout is the instance's job; `stackshot/projects/rename_page.py` and `stackshot/projects/page_keeper.py` are gbrain tools and refuse under plain with a message that says so. | |
| `pages.template_page` | `""` | The page whose Part 2 holds the project template a new project's page is made from (a key under the dirs, e.g. `"projects/template"`); empty = the short built-in page. | |
| `pages.rules_line` | `""` | The bullet a new project's page carries to link the rules, written as given; empty = `- Not written yet.` | |
| `pages.timeline_source` | `"stackshot"` | The source word on the timeline line a page move writes (`stackshot/projects/rename_page.py`; gbrain flavor). | |
| `pages.copy_project_lines` | `true` | The copy of a project's record onto its page's `display-name:`, `status:` and `agents:` lines, written after every project verb (`project_verbs.mirror`). `false` retires the copy on every brain at once: the record is the only place those fields live, and a script reads them with `stackshot projects fields <project>` (the record first, the page's lines for a project the record does not hold yet). A page of a brain marked `shared` never gets the copy, whatever this says. A new project's page is still made (`create --make-page`, `mirror --make-page`) on a brain not marked `shared`, with the template's lines and no copy onto it. | |

| `fleet.tool_name` | `""` | The fleet tool as the prose names it: the board's "Pane recycle pending for … (`<name>` runs it)", a session link's "open this session in `<name>`", the update tool's recycle text. `""`: "the fleet tool". Contract: none; it only changes prose. | if used |
| `fleet.recycle_when_idle` | `""` | The command, as words, that asks the fleet tool for a pane recycle once the box is idle, the reason appended (e.g. `"sala recycle --when-idle"`). Contract: [13, stackshot's release asks for a recycle](https://github.com/howardpark-ai/salamander/blob/main/docs/stackshot-contracts.md#13-stackshots-release-asks-for-a-recycle). | if used |
| `fleet.notice_cmd` | `""` | The command, as words like `recycle_when_idle`, that tells the running sessions about a change they should know but need not reload (a rule, a tool's wording). `release.sh` runs it after a green deploy whose session pick is a notice, with one argument appended, "<title> — <summary>" (a newline or tab turned into a space, cut to 400 characters and ending in "…" when cut), so a command like `sala notice add --from release` takes it as its one text argument ([docs/session-reload.md](session-reload.md)). | `release.report_to` | `"projects/example"` | The page key (or session name) `release.sh` sends the report of each release to, and names in the line it prints when a release starts. The default is the stand-in page of the example config; set a page of your own. A value that is not a page key or session name reads as the default (`stackshot/core/config.py` `notes()` and doctor say so). | |
| `subject.prefixes` | `["[work] ", "[home] "]` | Every subject starts with one of these. | yes |
| `subject.fallback_prefix` | `""` | The prefix of an item the server files itself (a pane's terminal prompt, a job gap) when the project's scope has no prefix of its own; it must be one of `subject.prefixes`. `""`, or one that is not in the list: the first prefix. | |
| `subject.max_length` | `80` | the longest subject a create or an update that sets one takes, the scope prefix counted; longer is refused with the limit, the length and the fix. A stored longer subject is left as it is: a write that does not set the subject is never refused for it. Before this the code default was 200 and the example file's 160. | |
| `close.reason_max` | `120` | the longest `reason` a close takes (`complete`, or `update` with `status=completed`); longer is refused. `0` = no limit. The server's own closes (done check, watcher drop, cold call, pane prompt) keep to it by cutting their text. | |
| `description.max_lines` | `8` | The hard ceiling on description lines (non-blank), refused above it. | |
| `description.line_max` | `120` | every description line must be a `- ` bullet of at most this many characters, else the write is refused. A link counts by its text (its destination does not, in any form: `(url)`, `(url "title")`, `(<url with spaces>)`, one level of parentheses in the url; nor does a naked URL). A dash followed by spaces or a tab is a bullet. A session's create, and an update that replaces the description, must also open with a `- Goal: …` first bullet (see "An item opens with its goal"). Only the description written in the call is checked, a close's new description included; a stored one is never judged. The client API's question route writes its text as bullets itself and is gated like any create; the cold call's close description is put into bullets before it is written (split on lines only, a leading `-`, `*`, `•` or `1.` marker taken off, each line clipped as it reads; more than `max_lines` lines end in `- …and N more`). | |
| `description.require_bullets` | `true` | `false` switches all of the description strictness off (a way back): the bullet and length checks, the refusal of a long `next` line (the old note returns), the question route's bulleting and clipping, and the cold call's re-bulleting; the line cap and `forbid_tokens` still apply, and the re-bullet pass goes back to its own checks. `[model] description_guard` is inert while this is `true`: a description that is not bullets is refused before that guard sees it, so the guard's note/refuse modes only matter with this set to `false`. The re-bullet pass holds its rewrites to `line_max` too, so the server does not refuse what the pass writes. | |
| `metadata.next.line_max` | `200` | a line of `next` over this many characters is refused, counted after its `<actor>: ` prefix (the text up to and including the colon-space that names the actor, so a long session name takes no room from the action; a line with no such prefix counts whole; the whole line is capped at this plus 80, 280 by default, since a name may be three long words) (`0` = off, and the old "a line over 200 characters" note returns) (links counted as in a description). Only the `next` written in the call is checked; a `<owner>: `command`` line (the whole command in one backtick span; any other line of his is prose and counts) and next's first non-blank line when it is an ask line and the call passes no `ask` are not judged. A hash, a test count or past tense stays a note. | |
| `metadata.next.require_marks` | `true` | `next` is a checklist; a write of `next` that no longer lists an open step, with the step not named in `done` or `dropped`, is refused. `false` is the way back: the step reads as dropped, with nobody and no time (as a line that left `next` by a write that knows nothing of steps does). | |
| `description.forbid_tokens` | `["resolved:", "done:"]` | Refused in a description, which is live state, not a changelog. | |
| `metadata.owner.required` | `true` | An item must name its creator session (stored as `metadata.owner`, shown in History as "created by"; it is not who moves the item). | |
| `metadata.project.required`, `.registry` | `true`, `"projects"` | An item must name a page found in the `projects` registry. | |
| `metadata.needs.enum` | `["decision", "external"]` | The kinds allowed in `needs` beside session names. | |
| `metadata.priority.enum` | `["p1", "p2", "p3"]` | The allowed priorities. | |
| `metadata.due.format` | `"YYYY-MM-DD"` | The format of `due`. | |
| `metadata.next.type` | `"string"` | `next` is free text. | |
| `registries.projects.key` | `"pages"` | The top-level key of `projects.json`, which the publisher writes from `paths.brain`. | |
| `registries.projects.match` | `["projects/{value}", "{value}"]` | How a bare project value is resolved to a page key, tried in order. | |

| `board_check.mode` | `"off"` | The end-of-turn board check: off, block (a working turn that left the session's open items untouched is asked once to update or confirm them, or to say `Board: no change, <reason>`), or note (the same question said at the next prompt instead of holding the turn). | `audit.enabled` | `false` | true: `install.sh` installs and starts the audit's timer, and `POST /audit/now` starts the audit run (or cues the audit agent, in agent mode); false: no timer (one installed earlier is disabled and removed) and a cue is refused. | if used |
| `audit.mode` | `"script"` | `"script"`: the audit is a script (field checks in code, one model call per suspect); `"agent"`: the earlier way, a cue to the audit agent. Switching back to `"agent"` is the rollback. Any other value reads as `"script"`. | |
